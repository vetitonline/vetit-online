# Read-only admin order overview

`/admin/orders` renders a responsive server-side overview using `/api/admin/orders`'s shared handler. The admin home links to it. English is the default. No JavaScript session cache, order mutation, payment control or scheduling registration is introduced.

The API authenticates with the existing Supabase auth helper and requires verified `app_metadata.vetit_admin` (`true` or `"true"`). User metadata and query-supplied roles do not grant access. A new, explicitly unapplied SQL proposal in `supabase/test-project/20261121170000_admin_order_overview.proposal.sql` independently checks the same trusted JWT claim and authenticated identity. The narrowly scoped SECURITY DEFINER function returns a projection of order summaries only, without granting new table access or mutation permissions. It does not expose customer IDs, contacts, addresses, payment records or provider evidence. Customer/seller APIs, row policies and hosted ordering/scheduling flags are unchanged.

Pages default to 20 orders with a maximum of 50. The existing customer cursor encoding and validation preserve PostgreSQL timestamp precision and UUID tie-breaking. The handler requests one extra record to detect an older page; malformed/duplicate backend rows fail closed. Responses and the server-rendered page are private and uncached. Unknown backend failures return a sanitized 503, with no privileged fallback. A missing hosted function therefore shows an unavailable overview rather than an apparently complete empty list.

Tests cover unauthenticated/non-admin denial, user-metadata spoofing, bounds/cursors, sensitive-field stripping, duplicate/invalid results, missing backend and revoked permissions. The disposable PostgreSQL suite installs the proposal only in a network-isolated container and tests real JWT-claim authorization, pagination, anonymous denial and lack of update permissions alongside existing customer ownership and seller pagination checks.

Remaining approval requirements: review and deploy the proposal to an approved environment, validate hosted PostgREST/Auth behavior and admin claim provisioning, then explicitly approve any production deployment. Global order mutation, admin refunds and payment-review operations are outside this read-only milestone. Existing order/shipping/tax/provider and scheduling launch blockers remain; hosted order creation and scheduling have not been activated.
