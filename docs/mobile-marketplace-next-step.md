# Vetit Online mobile app

The repository now contains a separate Expo/React Native application in `mobile/`. It consumes the existing, versioned `GET /api/catalog` endpoint through the shared client in `src/lib/marketplace/catalog-client.js`; mobile clients do not connect directly to Supabase.

The app provides marketplace home/category/subcategory discovery, search, species/category/INR price filters, sorting, pagination, product details, loading/error/empty states and a bounded in-memory preview cart with quantity controls. Public service discovery supports city/postcode/category search and availability checks. With the approved native session composition injected, the account/cart views also support verified order history/details, price-only quotes, moderation review, and read-only personal appointments/provider schedules. Native sign-in/storage require the explicitly approved injected adapters; the default preview retains its web handoff.

This is a Test-only candidate in every build mode. Set **both** `EXPO_PUBLIC_VETIT_API_BASE_URL` and `EXPO_PUBLIC_VETIT_TEST_API_ORIGIN` to the same approved Test-backed API origin. The production Vetit hostname and its subdomains are rejected. `http://localhost:4321` is a local workstation default; a physical device or Android emulator needs the appropriate reachable private LAN/emulator origin in both settings. Never overwrite an existing environment file. Mobile consumes the web API and does not need Supabase keys in its public configuration.

Reuse prior passing focused tests and the latest readiness report. Metro now exposes shared source/logo files outside `mobile/`. JavaScript bundle export, TypeScript and synthetic native-handler checks are distinct from device/Hermes/OS-storage and hosted-auth acceptance. Native provider booking confirmation/completion/cancellation now have confirmation, revision checks and uncertain-response reconciliation. Next unfinished work includes native provider slot/policy editing and seller catalogue management, product variants, persistent carts and operational checkout/payment. Other appointment writes remain in the signed-in web flow; browser handoffs use their own session. See `mobile/README.md` and `native-provider-appointment-actions-2026-10-20.md` for current results and concrete blockers.
